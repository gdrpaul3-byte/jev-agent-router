# 브라우저 작업 비교 촬영: Astra와 JEV + Astra

[English](BROWSER-DEMO.en.md)

## 실측 업무 시작점을 맞춰 비교하기

새 비교에는 `--task-clock`을 사용합니다. 양쪽의 0초를 공통 브라우저 준비가 끝나고 첫 모델 추론이 시작되기 전의 실측 업무 시작점에 맞춥니다. 최종 사실 추출·검증 뒤에 업무가 끝나며, 그 사이 추론과 대기 시간을 모두 1배속으로 유지합니다. 새 실행의 성공 여부·API 비용은 [별도 결과](../benchmarks/results/browser-task-aligned-20260924/RESULTS.md)와 [업무 시작점을 맞춘 비교 영상](../benchmarks/results/browser-task-aligned-20260924/comparison/comparison.mp4)에서 확인합니다. 아래에 보존한 이전 파일럿 수치는 새 실행의 측정값이 아닙니다.

이 모드는 원본 JPEG 프레임과 브라우저가 해당 화면을 표시한 시각을 `task-clock/manifest.json`에 기록하고, 실행 보고서가 그 해시를 참조합니다. Playwright는 콜백의 타임스탬프를 브라우저 표시 시점의 Unix epoch 기준 밀리초로 정의합니다. [Playwright screencast 공식 문서](https://playwright.dev/docs/api/class-screencast#screencast-start-option-on-frame).

업무 영상 렌더러는 매니페스트, 선택된 JPEG 해시, 업무 시작·종료 시각과 시계 일관성을 검사합니다. 출력의 매 40ms 지점마다 그 업무 시각 이전에 마지막으로 표시된 브라우저 프레임을 사용합니다. 따라서 **표본 프레임을 유지해 만든 25fps 영상**이며, 브라우저가 매초 서로 다른 화면 25개를 연속 제공했다는 뜻은 아닙니다. 화면 시간은 40ms 단위로 표현하고 영상 끝은 40ms 미만만큼 올림됩니다. 준비·정리는 업무 비교 영상에서 제외하지만 원본 녹화와 원시 캡처 근거에 보존합니다. 각 타이머는 실측 업무 종료 때 멈추고, 짧은 쪽은 마지막 화면을 유지합니다. 긴 쪽까지 끝난 뒤 양쪽 화면을 2초 더 보여줍니다.

아래의 `--task-clock` 명령으로 새 사전 검사와 양쪽 유료 실행을 기록한 다음, 성공한 실행을 각각 새 디렉터리에 렌더링합니다.

```sh
node -- benchmarks/render-task-clock-video.mjs "<run-directory>" "<new-output-directory>"
```

이 명령은 `task.mp4`와 `alignment.json`을 만듭니다. 해당 `task.mp4`에 `inspect-browser-video.mjs`를 실행해 또 다른 새 디렉터리에 검사 결과를 만들고, 완성 영상과 모음 이미지를 눈으로 확인합니다. 공개용 `astra/`·`jev/` 폴더에는 해당 실행 보고서, 검사된 `video.mp4`·`media.json`을 보존하고, 생성된 정렬 메타데이터를 `media.taskAlignment`에 넣습니다. 매니페스트 해시와 실측 시간은 바꾸지 않습니다. 단순 재생 영상에 업무 정렬 메타데이터를 붙이면 안 됩니다. 검토를 마친 양쪽 영상을 다음과 같이 합칩니다.

```sh
node -- benchmarks/render-browser-comparison.mjs --root benchmarks/results/browser-task-aligned-20260924 --output-dir "<new-comparison-directory>" --font "<path-to-Korean-font>"
```

렌더링·검사에는 `ffmpeg`·`ffprobe`와 설치된 한글 지원 글꼴이 필요합니다. 이 파일 처리 과정은 모델을 호출하지 않습니다. 새 벤치마크 실행에는 새 API 비용이 발생하므로 이전 파일럿과 별도로 보고합니다. 원본 녹화, 원시 캡처 매니페스트, 실패한 시도도 검토 근거로 보존합니다.

## 이전 파일럿: 원본 녹화

**이전 결과: 양쪽 측정 업무가 통과했고, 영상 모든 프레임을 디코딩한 뒤 표본 프레임을 시각 검토했습니다.** 방식별 한 번의 이전 파일럿에서 업무 시간은 Astra 26.69초, JEV + Astra 12.71초였습니다. 해당 실행의 [영문·국문 결과와 근거](../benchmarks/results/browser-playwright-20260924/RESULTS.md)를 참고하세요.

### 이전 영상을 함께 보기

[나란히 동시 비교 영상 재생](../benchmarks/results/browser-playwright-20260924/comparison/comparison.mp4): 왼쪽은 **JEV 미사용 — Astra**, 오른쪽은 **JEV 사용 — JEV + Astra**입니다. 원본 영상 전체가 재생 0초부터 함께 시작하고 1배속으로 진행합니다. 움직이는 초 표시는 **영상 재생 시간**이며, 실측 업무 시간은 별도의 고정 수치로 표시합니다. 영상에서 업무가 시작된 정확한 프레임 시차는 알 수 없으므로 업무 시작점을 맞춘 편집은 아닙니다.

각 원본 영상이 끝나면 해당 초 표시가 멈추고, 종료 문구와 함께 마지막 화면을 유지합니다. 긴 영상까지 끝난 뒤에는 양쪽 화면을 2초 더 보여줍니다. 완성 영상은 33.96초이며 원본은 변경하지 않았습니다. 기존 파일만 편집하므로 새 API 호출은 없습니다.

저장소 루트에서 같은 구성을 만들려면 `ffmpeg`·`ffprobe`가 `PATH`에 있어야 하며, 한글을 지원하는 설치된 글꼴을 지정해야 합니다. 아래 따옴표 안의 예시를 실제 경로로 바꾸세요. 출력 디렉터리는 아직 존재하지 않는 새 경로여야 합니다.

```sh
node -- benchmarks/render-browser-comparison.mjs --root benchmarks/results/browser-playwright-20260924 --output-dir "<new-output-dir>" --font "<path-to-Korean-font>"
```

렌더러는 원본 해시·프레임 수를 검증한 뒤 합본 MP4, 포스터, 검토용 모음 이미지, 편집 메타데이터를 만듭니다. 새 합본을 공개하기 전에는 완성 영상과 모음 이미지를 직접 확인하세요.

## 비교 범위

이번 파일럿은 Playwright로 **화면에 보이는 새 Chrome 창**을 열고, 각 방식에 새 브라우저 컨텍스트와 1600 × 900 뷰포트를 사용합니다. Playwright의 `recordVideo`로 실제 브라우저 뷰포트를 기록합니다. 사용자의 원래 Chrome 탭에 연결하거나 이전 진단의 native CUA 백엔드를 사용하는 실험이 아닙니다.

공개된 [화성의과학대학교 홈페이지](https://www.hsmu.ac.kr/web/main/index.do)에서 Astra 방식과 JEV 방식을 각각 한 번 완료했습니다. 이전 ABBA 제안과 구분되는 두 번의 파일럿이며 통계적으로 확립된 벤치마크가 아닙니다.

| 항목 | Astra 방식 | JEV 방식 |
|---|---|---|
| 다음 허용 행동·관측된 대상 선택 | OpenRouter를 통한 Astra | TypeSafe를 통한 JEV |
| 최종 사실 추출 | OpenRouter를 통한 Astra | OpenRouter를 통한 Astra |
| 브라우저 실행 | 표시되는 Chrome, 새 Playwright 컨텍스트 | 표시되는 Chrome, 새 Playwright 컨텍스트 |
| 뷰포트 | 1600 × 900 | 1600 × 900 |
| 업무·선택지·검사·한도 | 같은 확정 프로토콜 | 같은 확정 프로토콜 |

같은 제한된 선택지 안에서 실제 LLM으로 판단하는 대조군입니다. 자유로운 호스트 에이전트 추론, 기존 개인 브라우저 프로필, 봇 연결, 외부 양식 제출을 비교하지 않습니다.

## 행동 다섯 개와 사실 세 개 검증

호스트가 순서대로 허용하는 클릭은 다음과 같습니다.

1. `H` 메뉴 열기.
2. `총장 인사말` 페이지 방문.
3. `총장 인사말` 경로 표시줄의 하위 메뉴 버튼 열기.
4. `총장 프로필` 페이지 방문.
5. `오시는 길` 페이지 방문.

모델은 제공된 행동 ID와 현재 관측된 대상에서 선택합니다. 호스트는 새로운 페이지 근거와 URL·제목으로 방문 순서를 확인합니다. 모델의 확신만으로 성공을 인정하지 않습니다.

인사말과 프로필 본문은 이미지입니다. 해당 검사는 **페이지 방문만 확인하며 이미지 내용을 읽고 이해했음을 입증하지 않습니다.** 마지막 추출은 브라우저에서 관측한 오시는 길 텍스트를 사용하고, 다음과 같이 확정된 기대값과 대조합니다.

| 항목 | 이 프로토콜의 기대값 |
|---|---|
| 서울역 출발 버스 | `5101` |
| 대학 대표 전화 | `031-369-9100~1` |
| 셔틀버스 탑승요금 | `무료` |

기대값은 로컬 검증용 정답이며 추출 모델에 제공하는 힌트가 아닙니다. 사이트가 바뀌면 다음 측정 전에 확인하고 프로토콜 버전을 변경합니다. 결과를 본 뒤 검사 기준을 완화하지 않습니다.

일반적인 성공 경로의 예상 API 호출은 **방식별 7회**입니다. 행동 선택 5회, 완료 판단 1회, 최종 추출 1회입니다. 보장되는 호출 수는 아니며 실패나 허용된 재계획을 포함한 실제 시도는 모두 보고서에 남깁니다.

## 저장소 루트에서 새 업무 시계 실행 기록

Node.js 24 이상, 설치된 Chrome 채널, [설치 방법](INSTALL.ko.md)에 안내된 의존성이 필요합니다. 키는 비공개 `.env`에 둡니다. Astra 방식은 OpenRouter 키가 필요하고 JEV 방식은 TypeSafe 키도 필요합니다. 아래 명령은 독립 브라우저를 시작하며 기존 개인 탭을 재사용하지 않습니다.

저장소에 버전이 고정된 선택 의존성 `playwright-core`를 설치한 다음, 영상 인코더도 설치합니다.

```sh
npx playwright-core install ffmpeg
```

이 명령은 Playwright 녹화용 인코더를 설치합니다. Chrome은 별도로 설치되어 있어야 합니다. 뒤의 파일 검사 명령에는 **별도의 ffmpeg·ffprobe 실행 파일**도 필요합니다. Playwright 인코더 설치만으로 두 검사 명령이 `PATH`에서 실행 가능해지는 것은 아닙니다.

새 사전 검사 디렉터리를 만들고 보고서를 확인합니다.

```sh
node --use-system-ca -- benchmarks/record-hsmu-playwright.mjs --preflight --task-clock --output-dir benchmarks/results/browser-task-clock-preflight
```

같은 사전 검사 보고서를 사용하되, **각 시도마다 새 출력 디렉터리**를 지정합니다.

```sh
node --use-system-ca -- benchmarks/record-hsmu-playwright.mjs --arm astra --task-clock --env-file .env --preflight-report benchmarks/results/browser-task-clock-preflight/report.json --output-dir benchmarks/results/browser-task-clock-astra-1
node --use-system-ca -- benchmarks/record-hsmu-playwright.mjs --arm jev --task-clock --env-file .env --preflight-report benchmarks/results/browser-task-clock-preflight/report.json --output-dir benchmarks/results/browser-task-clock-jev-1
```

CLI는 소스 해시와 프로토콜을 사전 검사 근거로 확정하고 유료 실행에 사용합니다. 사전 검사와 양쪽 방식에 모두 `--task-clock`을 지정해야 하며, 이 옵션 없이 만든 이전 사전 검사로 대체하지 않습니다. 정확한 설정·소스 버전을 결과와 함께 보존합니다. 코드가 바뀌면 CLI를 새로 시작하며, 새 모듈과 이전 영속 런타임의 클로저를 섞어서 비교하지 않습니다.

기본 한도는 **방식별 예상 비용 $2, 요청 10회**입니다. 요청 한도는 시도한 POST를 제한하지만, 비용 검사는 공급자가 강제하는 선불 잔액 한도가 아닙니다. 실제 방식 실행에는 API 비용이 발생합니다. 실패하면 그 시도를 보존하고, 통과할 때까지 상태를 초기화하거나 조용히 재시도하지 않습니다.

## 시간·녹화·캐시 조건

측정하는 **업무 전체 시간**에는 브라우저 관측, 모델 판단, 클릭, 완료 검사, 최종 사실 추출·검증이 포함됩니다. 브라우저 프로세스·컨텍스트 준비, 최초 홈페이지 이동, 정리는 업무 타이머에서 제외하되 별도로 보고합니다. 양쪽의 같은 시간 구간을 비교합니다.

새 컨텍스트에서는 홍보 팝업 네 개가 메뉴를 가렸습니다. 공통 호스트 준비 과정은 새로 관측한 `X` 링크만 최대 여덟 번 닫고 업무 타이머를 시작합니다. 닫기 과정도 녹화하며 모델·API 요청은 하지 않습니다. 양쪽에 같은 준비를 적용합니다. 업무의 각 클릭 뒤에는 `DOMContentLoaded`를 기다린 후 새 관측을 받아 중간의 빈 본문을 읽지 않도록 합니다. 클릭을 반복 실행하는 처리는 아닙니다.

녹화에 포함된 초기 화면·홈페이지 이동부터 측정 업무와 실제 후행 구간까지 **1배속**으로 보존합니다. 브라우저 프로세스 시작은 첫 녹화 프레임보다 앞설 수 있으므로 해당 구간은 준비 시간으로 확인합니다. 기다리는 구간을 잘라내거나 페이지 순서를 삽입하거나 없는 프레임을 대체하지 않습니다. 녹화는 업무 전후도 포함하므로 영상 길이와 업무 시간은 다릅니다.

새 컨텍스트는 앞 방식의 브라우저 컨텍스트 상태가 다음 방식으로 이어지는 것을 피합니다. 운영체제·네트워크·사이트·공급자 캐시가 모두 비어 있다는 증거는 아닙니다. LLM의 `cacheMode: "off"`는 명시적인 프롬프트 캐시 경계를 요청하지 않는다는 뜻이며 **공급자의 캐시 토큰 0을 보장하지 않습니다.** 보고된 캐시 사용량을 보존하고 브라우저 캐시나 정확 결과 재생과 구분합니다.

## 공개 전에 각 실제 영상 검사

CLI가 기록한 실제 원본 영상 경로와 **새 검사 디렉터리**를 지정합니다.

```sh
node -- benchmarks/inspect-browser-video.mjs path/to/recorded-video.webm benchmarks/results/browser-pilot-astra-1-review
```

JEV 이동 구간의 더 촘촘한 모음 이미지를 포함해 표본 프레임을 눈으로 확인했으며, 공개 사이트만 보이고 계정·키·다른 앱은 보이지 않았습니다. 사람이 모든 프레임을 봤다는 뜻은 아닙니다. 보이는 로딩·팝업 준비·대기를 포함한 전체 기록을 자르지 않고 1배속으로 보존했습니다. 최초 인코딩 프레임의 시차는 미확정입니다. 보고서의 오프셋은 추정치이고 영상 길이가 업무 타이머는 아니므로, 이를 근거로 정확한 업무 시간 오버레이를 만들지 않았습니다.

방식별 한 번의 결과는 이 업무의 시연 근거이며 일반적인 속도 향상이나 비용 절감을 입증하지 않습니다. 업무·경로·기대값은 이 프로젝트가 작성했고 허용 경로는 미리 알려져 있었습니다. 독립 벤치마크, 이미지 이해, Claude 운영 연동, 원래 개인 브라우저 연결 복구를 입증하지 않습니다. 업무 보고서와 영상의 가시성·개인정보 검사는 별도의 근거입니다.

## 현재 사전 검사·녹화 진단

새 백엔드의 첫 무료 다섯 클릭 사전 검사는 관측값 전송 수정 전에 실패했으며, **유료 API 호출은 0회**였습니다. 조사 결과 HSMU 페이지가 `window.Map`을 기본 함수가 아닌 함수로 덮어썼고, `get`은 있었지만 `set`은 없었습니다. 해당 페이지에서 Playwright로 객체·배열을 반환하면 `undefined`가 됐지만 JSON 문자열은 정상적으로 전달됐습니다.

현재 DOM·제목 관측은 JSON 문자열로 전달하고 호스트에서 크기를 제한해 파싱한 뒤 엄격하게 검증합니다. 수정 전에 실패했던 회귀 검사 등을 포함한 집중 테스트 **52개가 통과**했습니다. 이 테스트는 관측된 데이터 전송 문제의 수정을 검증하며, 성공한 실측 업무에는 위의 별도 보고서를 제공합니다.

해당 진단의 브라우저 자체 녹화는 **11.6초·290프레임**이었고, 실제 모음 이미지에서 화면 내용을 확인했습니다. 브라우저 뷰포트 녹화로 불안정했던 데스크톱 `gdigrab` 캡처를 대체합니다. 이 진단은 녹화 근거이며 업무 성공 결과가 아니고, 원래 개인 탭·CUA 연결을 복구하거나 검증했다는 뜻도 아닙니다.

이후 **네 번째 무료 사전 검사는 성공**했습니다. 클릭 다섯 번과 세 목적지의 URL·제목 검사가 모두 통과했고 **API 호출은 0회**였습니다. 전체 녹화는 **17.28초·432프레임**, 검출된 검은 구간은 0이었으며 실제 모음 이미지를 눈으로 확인했습니다. 이는 앞선 11.6초 녹화 진단과 별도의 전체 이동 사전 검사입니다. 실패를 포함한 무료 사전 검사 네 번은 결과 폴더의 `preflight-1`부터 `preflight-4`에 보존하며 유료 API 호출은 없었습니다. 성공한 두 유료 방식은 같은 확정 소스·프로토콜 해시를 사용하고 별도 실행 보고서를 남겼습니다.

## 이전 진단 기록은 별도 보존

앞선 native CUA 진단 여섯 번에서는 **POST 23회**, OpenRouter 크레딧과 JEV 추정을 합산해 **$0.849577356**이 계상됐습니다. Astra 한 번은 업무를 통과했지만 JEV는 성공하지 못했고, 비교 녹화는 검은 화면이어서 유효하지 않았습니다. 성공한 비교 실험의 결과로 사용하지 않습니다.

이 기록에는 서로 다른 JS realm의 JSON 파서 문제 수정 전후와 설정 문제가 포함됩니다. 이전 영속 런타임 클로저가 남아 있어, 나중에 의도한 설정을 바꿨음에도 실제 관측 제한 시간이 5초로 유지됐습니다. 새로운 소스 해시 기반 CLI는 새 프로세스에서 실행해 실제 로드된 코드·설정을 검토할 수 있게 합니다. 이전 보고서·비용은 따로 보존하며 새 파일럿에 시간을 섞거나 영상을 대신 사용하거나 실패를 숨기지 않습니다.
